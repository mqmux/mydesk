# FFmpeg runtimes

LAN 4.20 adds MyDesk's key-based LAN target selection and an optional lightweight `key-match-v1` probe, using the existing Go TLS 1.3 channel-exporter/HMAC proof primitives with distinct match roles. UDP discovery carries only capability/identity metadata, not the pairing key, a key hash or its proof. Verified per-process identities merge addresses; probes do not reserve or replace a video session. Explicit-IP v6 pairing remains unchanged. This is MyDesk code with no new library, runtime, codec or third-party source. Existing pairing-code display on the host is retained; no new key-persistence file is added. FFmpeg, Windows MF/D3D11, clipboard, file transfer and the original cloud sources remain unchanged.

LAN 4.19 changes only MyDesk clipboard synchronization/read handling and diagnostic calls to installed Windows user32 APIs. Raw clipboard data is copied while open, then parsed/encoded/hashed after close; delayed/synthesized format sequence changes are sampled after retrieval. Occupancy diagnostics distinguish GetOpenClipboardWindow from GetClipboardOwner: a content owner is not necessarily the open-lock holder, and a NULL-window opener may be unidentified. No clipboard manager, extra library/runtime or process-termination behavior is added; the cloud source is untouched. API references: https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-openclipboard, https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-closeclipboard, https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getclipboarddata, https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getclipboardsequencenumber and https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getopenclipboardwindow.

LAN 4.18 adds MyDesk's bounded FIFO queue grace, short UDP batches with scheduler yields, resource-pressure retry, sender-owned NACK processing and optional local timing/cadence counters. No external source/library/runtime or codec configuration is added. Winsock retry classification follows numeric WSAENOBUFS (10055) and WSAEWOULDBLOCK (10035), including wrapped Go errors, not localized text or a blanket retry of fatal errors. API reference: https://learn.microsoft.com/en-us/windows/win32/winsock/windows-sockets-error-codes-2. No firewall/VPN/system timer-resolution setting is changed. The existing FFmpeg binaries and Windows MF/D3D11 paths remain.

LAN 4.17 changes remote F7/F8 directory memory to a mutex-protected host-process object only: no sidecar/AppData settings are read or written, reconnects retain values, and host restart resets them. This is MyDesk code with no new dependency or runtime change. Capture, codec, shared-GPU display and resolution-change handling remain unchanged.

LAN 4.16 refreshes desktop geometry before pairing and on display-mode changes, using installed Windows MONITORINFOEXW/GetMonitorInfoW/EnumDisplayMonitors and the existing DXGI output descriptors. Device names preserve selection across rectangle/index changes; one reusable enumeration callback avoids repeated allocation of Go Windows callback slots. The change watcher, generation/input synchronization, current-profile probe and SPS size guard are MyDesk code. No external library/runtime or Windows display settings are added/changed. Original capture/encoder options, Windows MF/shared-texture rendering and FFmpeg distributions are retained.

LAN 4.15 adds MF/D3D11 shared GPU texture output using Windows-provided IMFDXGIBuffer, ID3D11Texture2D, IDXGIResource and IDXGIKeyedMutex. Three private BGRA surfaces separate the decoder's sample ownership from the viewer. NV12 colour conversion, cumulative repair motion masks, bounded local timings and remote directory persistence are MyDesk code. API declarations/GUIDs follow the Microsoft Windows SDK; no Microsoft DLL, third-party source, CUDA or additional codec/runtime is bundled. References: https://learn.microsoft.com/en-us/windows/win32/api/mfobjects/nn-mfobjects-imfdxgibuffer, https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11device-opensharedresource and https://learn.microsoft.com/en-us/windows/win32/api/dxgi/nf-dxgi-idxgikeyedmutex-acquiresync. Shared textures still require GPU copies and synchronization; this does not claim a completely copy-free pipeline. The original CPU output and FFmpeg fallback remain.

LAN 4.14 restores continuous ddagrab capture (`dup_frames=1`) after user-reported dragging regressions with 4.13's update-driven mode (https://ffmpeg.org/ffmpeg-filters.html#ddagrab). Savings now apply only to minimized rendering/repair sampling and idle UDP polling; no production update-driven capture switch remains. No FFmpeg source, new runtime, DLL or codec library is added. Authenticated UDP keepalive and minimized repair scheduling are MyDesk code. The desktop capture/encoder process remains alive; this is not a new native capture backend.

LAN 4.11's virtual Unicode ListView uses the installed Windows Common Controls v6 via a thread-local activation context. The embedded manifest text is MyDesk code; a private temporary manifest is removed when the F8 window closes. No comctl32 DLL or external manifest is distributed. API reference: https://learn.microsoft.com/en-us/windows/win32/controls/list-view-controls-overview.

LAN 4.10 additionally uses the Windows-provided Media Foundation H.264 MFT, COM and DXGI device-manager APIs. No Microsoft decoder DLL or third-party codec source is bundled; the native route calls installed Windows components from Go without CGo. API declarations/GUIDs follow the Windows SDK. References: https://learn.microsoft.com/en-us/windows/win32/medfound/h-264-video-decoder and https://learn.microsoft.com/en-us/windows/win32/medfound/supporting-direct3d-11-video-decoding-in-media-foundation. The SPS metadata parser and bounded NV12 packing/normalization are MyDesk code; 4.10's CPU-output route remains the compatibility path for 4.15's shared textures. FFmpeg remains the optional controller fallback and the existing host encoder runtime.

LAN 4.6–4.8's native D3D11 renderer, HLSL NV12 conversion/scaling/enhancement, frame mailbox and local AVC pipe parser are MyDesk implementation code. CrossDesk and Moonlight were architectural references, not copied source or bundled dependencies. No Slint, SDL, MiniRTC, CUDA or new codec libraries were added. D3D11 and D3DCompiler are loaded from Windows system components; shader source is embedded in the controller EXE. The explicit NV12 colour contract follows FFmpeg's scale-filter controls (https://ffmpeg.org/ffmpeg-filters.html#scale) and Microsoft's 8-bit YUV guidance (https://learn.microsoft.com/en-us/windows/win32/medfound/recommended-8-bit-yuv-formats-for-video-rendering). Encoder-side local FLV/AVC framing uses the supplied runtime's FLV muxer (https://github.com/FFmpeg/FFmpeg/blob/master/libavformat/flvenc.c); no FFmpeg muxer source is copied into MyDesk and the network protocol remains unchanged.

This project invokes FFmpeg as a separate executable. The supplied Windows builds are provided by GyanD, a distributor linked from https://ffmpeg.org/download.html, and licensed GPLv3. Their license text is in the release folder as FFmpeg-LICENSE.txt. Upstream license and source access: https://ffmpeg.org/legal.html and https://github.com/FFmpeg/FFmpeg.
